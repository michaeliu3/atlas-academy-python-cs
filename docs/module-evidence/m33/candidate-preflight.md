# M33 authoring-only candidate evidence preflight

## Authoring candidate boundary

This document records an M33 **candidate-only structural evidence package**.
It binds the hidden formal-languages, computability, and complexity workbook
draft, its instructor-facing source research, its six-session/output topology,
its module companion, and a bounded formal-languages reference fixture/test to
inspectable local paths. It does not change M33's canonical state: M33 remains
`authoring-only`, `hidden` from the reader, and unreleased.

Nothing here adds M33 to the learner manifest, opens a route, creates a
learner-facing studio, turns its instructor source research into the canonical
graph source map, approves learner delivery, or changes the graph's release
tuple.

## What this candidate package can establish

- It declares grounded anchors for all eighteen module-contract criteria in
  the hidden M33 draft, including prerequisite repair, six sessions,
  first-principles formal-model separation, proof/assumption/counterexample
  boundaries, visual prose alternatives, diagnostic/retrieval draft, dossier,
  oral-defense prompts, companion handoff, and a bounded reference model/test.
- The hidden delivery map checks that each declared session has a visible typed
  local output and that prerequisite-bridge artifacts appear in their first
  consuming sessions. It is an authoring topology check, not a learner-delivery
  decision or quality review.
- The source material is explicitly instructor-facing candidate research. It
  provides source, claim, assumption, counterexample, and reuse planning
  context; it is not a canonical source-map binding or completed learner-facing
  source review.
- The Node fixture/test makes selected finite traces inspectable. It is not an
  interactive learner studio, a theorem oracle, a browser test, or evidence
  that CI has run for any candidate commit.

## Explicit nonclaims

- This dossier does not establish mathematical, pedagogical, source, license,
  visual, accessibility, browser, oral-defense, or interaction quality of the
  draft.
- No learner has thereby entered M33, completed its draft sessions, passed an
  oral defense, demonstrated mastery, or created a portfolio artifact.
- This dossier does not bind a source commit to successful CI, source review,
  private deployment, security review, release record, or publication.
- It does not claim any Codex Teaching Assistant or Study Partner chat used
  voice, a particular model setting, a rendered whiteboard, or automatic
  Notion capture.

## Required path before promotion

1. Keep M33 authoring-only and hidden until a reviewed delivery design supplies
   a separate fixed hidden review-candidate selector, canonical learner source
   ledger, and appropriate learner-facing interaction or equivalent, without
   weakening prerequisite gates. That selector must not reuse this authoring
   workbook or its authoring-delivery map as promotion authority.
2. Conduct explicit independent review of the workbook, source/claim/license
   boundaries, visual and accessibility behavior, diagnostic/rubric quality,
   and the TA/Study Partner/oral-defense flow on a preserved review-ready
   commit.
3. Add a learner manifest/route only after the reviewed contract, tests,
   accessibility checks, and release requirements are satisfied; preserve the
   exact reviewed commit as an ancestor.
4. Collect exact-source-commit CI, source-review, private-deployment,
   limitations, changelog, and provenance evidence in later additive records
   before describing M33 as published or released.
