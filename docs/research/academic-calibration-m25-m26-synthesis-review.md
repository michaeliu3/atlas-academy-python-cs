## Route and evidence-chain result

**The planned synthesis is coherent and currently correctly gated.** M25's
direct graph prerequisites are M22, M24, M30, M31, M34, M35, and M36; their
transitive closure includes M27–M36. M26 directly requires M25. M36 hands
forward to M25. M25/M26 have preview/reference access, while M31–M36 are
hidden and authoring-only. The reader projection retains prerequisite numbers,
does not link through a hidden route node, and tests M25 as a reference and M31
as unavailable. No active learner bypass was found.

The compact `M24 → M32 → M33 → M34 → M35 → M36 → M25 → M26` wording is also
coherent: M31 is already sequence position 22, before M18–M24, and M32 names
M31 as an academic prerequisite. It is a downstream navigation segment, not a
replacement for the full prerequisite closure.

M25/M26 consistently require an unavailable receipt to yield **DEFER** or
**NARROW CLAIM**, rather than treating the candidate packs as learner evidence.
That preserves the intended AI-era discipline: a theorem, metric, benchmark,
agent response, or green test does not gain authority by itself.

it must be made precise before a learner uses the final dossier.

One separate provenance ambiguity remains: the architecture record calls v2
the sole active graph and v1 a frozen historical fixture, while the older

The portal does not use that fixture, so this is not an active gating defect;
it could mislead a later release review because v1's M25/M26 lifecycle wording
is older.

The source set confirms that M25/M26 emphasize the right things—problem
formulation, specifications, review, reproducibility, evaluation, maintenance,
and communication—rather than a polished demo. It also confirms the honest
limitation: a 60-day private course cannot supply their sustained problem
volume, team interaction, live-system work, or institutional assessment.

## Lean improvements

1. **Repair the historical-audit label, not the learner route.** Point the
   M31–M36 readiness snapshot at v2 or label its v1 input a frozen historical
   fixture. Keep v2 as the sole active graph; do not add another graph.
2. **Make the existing Claim Join resolvable.** Refer to existing M35/M36
   output IDs (or one displayed name derived from them) in M25/M26's current
   receipt tables, then validate those references with the existing contract
   machinery—no new registry or studio.
3. **Reweave only after the gate can be honest.** Once M31–M36 have
   learner-ready evidence, run one focused M25/M26 revision that fills one
   real Claim Join and changes a release/defer decision under a changed
   premise. Recheck the sources above for scope; do not copy their protected
   course assets or imply equivalence.
